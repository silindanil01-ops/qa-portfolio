# Reservation Lab

Учебный проект для практики Manual + Automation QA. Сервис резервирования товара позволяет проверить одну бизнес-операцию на уровнях UI, HTTP API и БД. Стенд и тесты подготовлены с помощью Codex при развитии портфолио. Это не коммерческий проект и не продукт для публичного размещения.

## Проверяемые риски

| Риск | Проверка |
|---|---|
| Повтор запроса уменьшает остаток дважды | Один Idempotency-Key и одинаковые данные → прежний резерв |
| Другие данные с прежним ключом перезаписывают резерв | 409, остаток не меняется |
| Повторная отмена возвращает товар ещё раз | Остаток восстановлен только один раз |
| Два покупателя резервируют больше наличия | Параллельные HTTP-запросы → один успех и один 409 |
| Ошибка валидации оставляет запись в БД | Проверка ответа, остатка и количества строк |
| UI показывает успех при ошибке | Бизнес-ошибка и обрыв сети в браузере |
| API и БД расходятся | JOIN и агрегация активных резервов |

## Запуск

Установка — в [главном README](../README.md). Точные версии записаны в `requirements-lock.txt`, диапазоны для обновления — в `requirements.txt`. Все проверки:

```bash
python -m pytest --browser chromium --tracing retain-on-failure --screenshot only-on-failure --junitxml=test-results/results.xml
```

Только API и SQL: `python -m pytest -m "api or sql"`.
Только UI: `python -m pytest -m ui --browser chromium`.

Для ручной практики:

```bash
python -m automation.lab.app --port 8000
```

Открыть `http://127.0.0.1:8000`. Данные — в `lab.sqlite3`; для сброса остановить стенд, удалить только этот учебный файл и запустить снова.

## Устройство

- `lab/` — объект тестирования: Flask и SQLite, настоящий HTTP.
- `client.py` — requests с таймаутом; автоматических повторов нет.
- `tests/conftest.py` — отдельная база и сервер для каждого теста, очистка после выполнения.
- `tests/test_api.py` — контракт JSON, валидация, ошибки, жизненный цикл, повтор и конкуренция.
- `tests/test_sql.py` и `sql/` — инварианты данных, JOIN, CTE, оконная функция.
- `pages.py` и `tests/test_ui.py` — Page Object, доступные локаторы, ожидания Playwright без sleep.
- `../.github/workflows/tests.yml` — API/SQL на Python 3.11 и 3.12; отдельный Chromium job и артефакты ошибок.

## Границы демонстрации

Сервер слушает только 127.0.0.1. У него нет аутентификации и модели прав; используются вымышленные данные example.com. SQLite и локальные конкурентные запросы не подтверждают опыт PostgreSQL, распределённых транзакций или нагрузочного тестирования. Playwright здесь проверяет веб-интерфейс, не нативные приложения. Kafka, gRPC, Java и C# в проекте не реализованы.

CI считается проверенным только после фактического запуска в GitHub Actions. Локальные результаты — в [verification.md](verification.md).
