# Mobile QA для приложения поиска смен

Тестовая модель для **условного** приложения, где исполнитель выбирает смену и записывается на неё. Она подготовлена как пример подхода к вакансии [Ozon Job](https://getmatch.ru/vacancies/36247-inzhener-po-testirovaniiu-ozon-job), а не как результат тестирования приложения Ozon: требований, сборок и тестовых аккаунтов компании у автора этого пакета нет.

## Что проверять в первую очередь

Основной пользовательский путь — список доступных смен → детали → запись → подтверждение. Ошибки могут приводить к двойной записи, потере смены, неверному статусу после обрыва сети и расхождению между устройством и сервером. Проверки ниже охватывают платформенные состояния приложения: разрешения, возврат из фона, восстановление сети, несколько размеров экрана и push/deep link, если они предусмотрены продуктом.

При появлении реальной сборки и спецификации сначала заполнить вопросы в рисках, затем выбрать матрицу, выполнить тесты и записать результаты по каждой сборке. Скрипт adb не запускался на реальном устройстве в рамках этого пакета. Для iOS используется Xcode Simulator или физическое устройство; никакого автоматического прогона iOS здесь нет.

Для Python-автоматизации и CI в портфолио есть отдельный [локальный веб/API стенд](../automation/README.md). Его Playwright-тесты работают с браузером, а не с нативным приложением.

Официальные инструменты: [Android Debug Bridge](https://developer.android.com/tools/adb), [Apple XCTest](https://developer.apple.com/documentation/xctest), [Xcode Simulator](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices).
