# Риски и критерии мобильного сценария

**Модель, не спецификация Ozon Job.** До выполнения проверок нужно согласовать правила записи на смены: может ли один человек занимать две пересекающиеся смены, как долго действует бронь, что происходит при отключении сети после нажатия кнопки и нужны ли подтверждения от сервера.

| Приоритет | Риск | Вопрос к требованиям | Проверка |
|---|---|---|---|
| P0 | Двойная запись после повтора запроса | Есть ли ключ идемпотентности? | Двойное нажатие, повтор после таймаута, одна запись в API |
| P0 | «Успех» на экране без подтверждения сервера | Как UI показывает неопределённый результат? | Обрыв после отправки; перепроверка статуса |
| P0 | Одновременная запись на последнее место | Кто и когда фиксирует лимит? | Два устройства с разными аккаунтами |
| P0 | Потеря статуса при возврате из фона | Когда приложение обновляет данные? | Свернуть во время запроса, вернуться, обновить |
| P1 | Некорректная смена или дата | Часовой пояс смены, DST, локализация | Граница суток, смена часов, другой часовой пояс |
| P1 | Ошибка при отказе в push-разрешении | Push обязателен или дополнительный канал? | Отказать / разрешить / изменить в настройках |
| P1 | Сломанный deep link из push | Авторизованное и неавторизованное состояние | Открыть уведомление, проверить нужную карточку |
| P1 | Утечка данных другого пользователя | Как ограничен доступ к чужой смене? | Сменить аккаунт; проверить кэш, deep link, API |
| P2 | Текст или кнопка недоступны | Поддерживаемый размер шрифта и доступность | Крупный шрифт, VoiceOver/TalkBack, ориентация |

## Допущения для учебных кейсов

Чтобы у сценариев было проверяемое ожидание, **в учебной модели** приняты правила: запись успешна только после ответа сервера; повтор запроса не создаёт вторую запись; отказ в push не блокирует запись; при пропаже сети статус не выдумывается, а перепроверяется после восстановления связи. Если реальная спецификация задаёт другое поведение, ожидаемый результат меняется только после её уточнения.

## Критерий готовности к релизу для примера

P0-прогоны прошли на поддерживаемых версиях обеих платформ; по P1-дефектам есть решение команды. Указываются номер сборки, модель устройства, версия ОС, сеть, тестовый аккаунт и идентификатор прогона. Фактические результаты и решение о релизе для Ozon Job здесь **не заявлены**.
