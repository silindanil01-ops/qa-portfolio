# Требования учебного сервиса

Эти правила определены для Reservation Lab. Они не относятся к DemoQA или системам работодателей.

| ID | Правило |
|---|---|
| R-01 | В новой БД TEA-001 имеет остаток 10, CUP-001 — 3 |
| R-02 | Резерв содержит sku, integer quantity от 1 до 100 и email вида local@domain.tld, до 254 символов, без пробелов |
| R-03 | POST требует JSON и непустой Idempotency-Key не длиннее 80 символов |
| R-04 | Новый корректный резерв → 201, active, уникальный id; остаток уменьшается на quantity |
| R-05 | Повтор с тем же ключом и данными → 200, тот же id и текущее состояние, без повторного списания |
| R-06 | Прежний ключ с другими данными → 409 idempotency_conflict |
| R-07 | Неизвестный товар → 404; недостаточный остаток → 409; неверные поля → 422 |
| R-08 | DELETE отменяет резерв и возвращает товар. Повторная отмена → 200, cancelled, без дополнительного возврата |
| R-09 | Повтор создания отменённого резерва с прежним ключом не активирует его заново |
| R-10 | Остаток неотрицателен, включая одновременные запросы; остаток + активные резервы = исходный запас |
| R-11 | GET и DELETE неизвестного резерва → 404 |
| R-12 | UI показывает успех, бизнес-ошибку или ошибку сети; после ошибки сети доступен повтор |

Пополнение склада, платежи, доставка, авторизация и удалённая БД вне области версии.

## HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/health | Готовность сервера |
| GET | /api/products | Каталог и остатки |
| POST | /api/reservations | Создать или повторить резерв |
| GET | /api/reservations/{id} | Получить состояние |
| DELETE | /api/reservations/{id} | Отменить резерв |

Пример запроса: `{"sku":"TEA-001","quantity":2,"email":"qa@example.com"}`.
Ошибка: `{"error":"insufficient_stock"}`. Резерв: id, sku, quantity, email, status.
